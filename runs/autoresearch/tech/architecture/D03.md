# D03 — Component Orchestration and the Ownership Contract

Who calls whom, and — the part that matters forensically — who is allowed to write which file. From repo `ARCHITECTURE.md` ("Dashboard Files Update Mandate").

```mermaid
flowchart LR
    HUMAN["Human technical lead<br/>dashboard reviews + steering [exists]"] -.->|natural language| AGENT

    subgraph AGENTSIDE["Agent responsibilities - reasoning plane"]
        AGENT["Steering agent / coding assistant<br/>bound by 52-section constitution [exists]"]
        JOURNAL["research_journal.md<br/>experiment_summary.md [exists]"]
        PREANN["pre-run reasoning annotation [exists]"]
    end

    subgraph CODE["Deterministic core - execution plane [exists]"]
        RUNNER["core/runner.py<br/>one experiment per invocation"]
        REAS["core/reasoning.py<br/>validators: citation + completeness"]
        EVAL["core/evaluation/<br/>splits, metrics, composite, uncertainty"]
        BBR["core/backbones/registry.py<br/>create_model factory"]
        CKPT["CheckpointManager<br/>core/checkpoint.py - resume file + summary"]
        WA["Winner archiver<br/>core/winner_archive.py - 14-section audit report + bundle"]
    end

    subgraph DISK["Disk truth - append-only where it matters"]
        LEDGER["experiment_log.jsonl [exists]"]
        ANNJ["reasoning_annotations.json [exists]"]
        CKF["project_autoresearch_checkpoint.md [exists]"]
        WINDIR["winners/ bundles [exists]"]
        DASH["dashboard.html - reads only [exists]"]
    end

    AGENT -->|writes| PREANN --> REAS
    AGENT -->|invokes with config| RUNNER
    RUNNER --> REAS
    RUNNER --> EVAL
    RUNNER --> BBR
    RUNNER -->|append row| LEDGER
    RUNNER -->|fallback sentinel only| ANNJ
    RUNNER -->|champion only| WA --> WINDIR
    AGENT -->|writes| JOURNAL
    AGENT --> CKPT --> CKF
    LEDGER --> DASH
    ANNJ --> DASH
    DASH -.->|read| HUMAN
```

**What a reviewer should notice:** (1) the reasoning plane (LLM) and the execution plane (deterministic Python) are separated, and the *execution plane owns the ledger* — the agent may not, **by contract**, write a result row; it invokes the runner, which writes what actually happened. Stated honestly: the JSONL has no OS-level ACL, so this is an ownership *contract* with a tamper-evidence backstop (per-row fingerprints, git history, append-only diffing), not technical prevention — hard enforcement is a sandbox property [D32], roadmap; (2) the runner's only write into the reasoning file is a `TODO-REWRITE` sentinel — it never fabricates reasoning; (3) the dashboard is read-only over disk truth, so what the human monitors is what the runner wrote, not what the agent claims; (4) this ownership split is why "the agent audited itself" is not the trust model — the deterministic core audits the agent, and violations of the contract are designed to be loud rather than impossible.
