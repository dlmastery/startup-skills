# D02 — The 7-Step Closed Loop with Audit Gates

The constitution's scientific method (sections 23–29) as a control loop. Everything here exists in the PoC; the trial-count-corrected threshold is the one planned addition, marked.

```mermaid
flowchart TD
    START(["Session start: read checkpoint,<br/>hardware log, ledger tail - never assume state"]) --> S1

    S1["1 DIAGNOSE<br/>per-fold / per-regime weakness<br/>analysis of current champion"] --> S2
    S2["2 LITERATURE-GROUND<br/>arXiv + SOTA catalog search,<br/>full citations required"] --> S3
    S3["3 HYPOTHESIZE<br/>exactly ONE minimal change +<br/>quantitative prediction on composite"] --> PRE

    subgraph PRE["Audit gates - pre-execution [exists]"]
        GA["Gate 1 data integrity<br/>split overlap, feature cache, GPU pre-flight"]
        GB["Gate 2 citation rigor<br/>authors, year, venue, title, arXiv, relevance"]
        GC["Gate 3 reasoning completeness<br/>word floors + required prediction"]
    end

    PRE -->|any gate fails| DISC1["DISCARD before compute<br/>violation logged"] --> S1
    PRE -->|all pass| S4["4 EXECUTE<br/>fixed-duration run, one config"]

    S4 --> S5["5 ANALYZE<br/>observed vs predicted,<br/>explain the discrepancy"]
    S5 --> S6["6 DOCUMENT<br/>reasoning blob committed<br/>to annotations file"]
    S6 --> KEEP{"composite &gt; champion<br/>on frozen fingerprinted formula?"}

    KEEP -->|no| DISC2["DISCARD - row stays in ledger"] --> S7
    KEEP -->|yes| DEFL{"clears trial-count-corrected<br/>acceptance gate - DSR panel<br/>shows raw + deflated? [planned]"}
    DEFL -->|no| NEAR["NEAR-MISS - re-evaluate<br/>with more seeds/paths [planned]"] --> S7
    DEFL -->|yes| WIN["KEEP: new champion<br/>winner archiver: bundle + audit report [exists]"] --> S7

    S7["7 CHECKPOINT<br/>overwrite resume file with<br/>exact next command"] --> S1

    STEER["Human steering - natural language only<br/>pivot / research / self-reflect [exists]"] -.-> S1
    CRASH["Crash / BSOD at any point"] -.->|resume from checkpoint| START
```

**What a reviewer should notice:** (1) the loop has *two* gate points — validity is checked before compute (gates) and improvement is checked before commit (fingerprinted composite), so neither an invalid nor a non-improving change can enter the champion line; (2) the keep decision compares against a cryptographically frozen formula the agent cannot rewrite mid-run; (3) the planned deflation diamond is where the multiple-testing critique (survey §6, [D6][D7]) becomes an enforced threshold rather than a caveat; (4) human steering enters at exactly one point, as data, and the crash path re-enters at session start — the loop is re-entrant by construction.
