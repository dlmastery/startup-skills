# Pivot log — Ascent (decision journal)

> **What this is** — the decision journal: five options already killed with the evidence that killed them, plus six standing pivot-or-persevere triggers that fire on dates.
> **Why it exists** — it stops the pack re-proposing a secret constitution or flat-rate hosted Pro once the reasoning fades, and it pre-authorizes the Karpathy branch so a channel pivot needs no deliberation the day it fires. ## Standing pivot-or-persevere criteria

Recorded verbatim from the strategy layer; these fire on dates, not moods. Day 1 = ascent v0 public launch (target: week of 2026-09-01, gtm §4).

1. **Trust-test gate (sessions weeks 10–13, ending ~day 91; D-CALENDAR):** "if <5/15 trust-test practitioners reproduce (test fails per BRIEF), stop the paid path and fix the proof artifact, not the marketing" (gtm §4). Full pass additionally requires ≥3/15 own-private-data runs and ≥8/15 named deploy-evidence (E1). Fail = persevere on product, pivot the proof artifact; it is not a company kill.
2. **Recalibrated open-core kill trigger (month 6 of maintained-successor work, ≈ 2027-03-01):** "measure active users directly (cloned + ran a campaign within 90 days). If after 6 months of maintained-successor work EITHER paid conversion is <0.5% of measured active users (bottom half of [C32]) OR the active base itself cannot be grown past ~3,000 despite maintenance and published bundles, the open-core model (A2) is wrong — escalate to ASSUMPTIONS.md before building enterprise features" (market_sizing §6). Same trigger governs revisiting the deliberately unfunded channels (paid social, outbound SDR — gtm §3).
3. **Pre-order gate (window days 110–120, closing ≈ 2026-12-29; E1 tally by ~day 100; D-CALENDAR):** <30 pre-orders or <5 design partners from a passed trust test (E4) → do not build hosted dashboards; rework the offer/pricing (A12 is "pricing rework only"), re-run the gate.
4. **Karpathy branch (standing, any date):** if Karpathy returns or blesses a different fork — congratulate publicly, keep upstream compatibility, shift acquisition weight to the pre-written plan-B channel (direct quant/ML communities: r/quant, QuantConnect/Numerai, SSRN/arXiv-adjacent) where the audit/DSR story stands without the repo (gtm §4 fork etiquette). This is a channel pivot, pre-authorized; no deliberation needed on the day.
5. **DSR branch (before first public bundle, weeks 1–4):** if the deflated EUR/USD number is weak (or the discard ledger is incomplete), lead with fraud-vs-AutoGluon and run EUR/USD as the methodology showcase; if discards weren't logged, the public deliverable is "DSR on a fresh instrumented run," stated plainly (positioning §4.2 / gtm §2.1). Pre-decided; seeing the number changes nothing about the rule.
6. **Threshold-integrity rule (standing):** any change to a pre-declared experiment threshold after data exists is itself a pivot decision — logged here with rationale, never edited in place on the experiment board.
