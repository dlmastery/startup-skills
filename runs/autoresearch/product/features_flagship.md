# Ascent — 20 Flagship Features

> **What this is** — The twenty features that carry Ascent, each as mechanism → principle → the literal moment a user sees on screen.
> **Why it exists** — Every feature here is individually copyable — the constitution is open source by design — so the file must show why the closed loop is the product: drop the ledger and champions inflate; drop Gate 2 and citations fabricate.
> **How to read it** — Read "The integration argument" first, then attack which moments are demoable: #2, #3, #11 and #12 are roadmap, and PoC numbers are founder-reported.
> **Depends on / feeds** — Expands [PRD.md](PRD.md) §6; sequenced by [features_prioritized.md](features_prioritized.md); consumed by [ux_spec.md](ux_spec.md) and [technique_feature_matrix.md](../tech/techniques/technique_feature_matrix.md).

Format per feature: **name** → mechanism → principle(s) (PRD §5) → the visible product moment (what the user literally sees). Source tags as in PRD. PoC metrics founder-reported (A6).

1. **Trial ledger (discards included)** → append-only `experiment_log.jsonl` records every experiment — kept *and* discarded — with seed, config, git commit, gate verdicts; the ledger is the denominator every honest statistic needs [D6][D9] and the raw material of the calibration corpus (A11) → P2 → *Moment:* the dashboard header always shows "Trial 218 of this campaign — 9 kept, 209 discarded"; nothing is ever quietly deleted.
2. **Trial-count-corrected acceptance gate** → the keep/discard threshold rises with ledger count (deflated-composite analogue of the DSR [D6][D7]); a candidate that would have been kept at trial 20 is rejected at trial 220 unless it clears the inflation-adjusted bar → P2 → *Moment:* a rejection card reading "Improvement +0.011 < deflated threshold +0.019 at N=218 trials — discarded; logged to ledger." **No published system has this gate [survey §6]; it is the roadmap differentiator.**
3. **DSR / deflated-statistic panel** → computes the deflated Sharpe ratio (finance) or trial-count-corrected analogue (other metrics) from the true ledger count and displays it beside every raw champion figure → P2 → *Moment:* the champion card reads "Sharpe +6.52 raw · deflated X over 265 trials — full ledger attached," never the raw number alone (positioning.md §4.2).
4. **Super-fold split builder** → visual constructor over `SuperFoldSplit`/`WalkForwardSplit` with purge, embargo, and label-horizon buffers [D8]; `validate_no_overlap()` runs programmatically and the runner refuses to launch on any overlap → P1 → *Moment:* a timeline diagram with purge/embargo bands drawn on the user's actual dates, and a green "0 overlapping rows across 7 folds — verified" stamp.
5. **Three pre-commit audit gates** → Gate 1 data integrity (split geometry, hash checks — deterministic), Gate 2 citation rigor (every reference verified against live indexes [B24][D35]— deterministic), Gate 3 reasoning completeness (word/field floors — deterministic floors plus LLM screen, labeled as a screen [D33]) run before any commit; failing any gate discards the experiment with the verdict logged → P5, P1, P3 → *Moment:* three gate chips (green/red) on every experiment row; clicking a red chip shows the exact violation text.
6. **Constitution instantiation wizard** → 12-step guided flow (from the PoC skill) asks task, metric, split protocol, hardware, rigor vocabulary, and emits the domain-adapted 52-section constitution plus folder skeleton, starter runner, and dashboard → P1, P5, P7 → *Moment:* twenty minutes after install, Priya sees "Your constitution: 52 sections, 4 adapted for single-cell AUROC — review sections 12, 23–29" and a runnable campaign.
7. **Constitution editor with locked invariants** → section-blocked editor mirroring the paper's App. A.1 structure; audit-gate and metric sections are read-only once a campaign starts (runner enforces PoC rule 9) → P4, P5 → *Moment:* attempting to edit §36 mid-campaign shows "Locked while campaign live — the agent can't change this either."
8. **Verified literature grounding** → the Ground step retrieves from OpenAlex/Semantic Scholar/arXiv [B24]; Gate 2 rejects any citation that fails live-index verification (fabrication rates run 14–95% ungated [D35][D36]) → P3, P5 → *Moment:* every hypothesis card lists its citations with resolving links and a "verified against index" tick — or the experiment never ran.
9. **Deficiency diagnosis heatmap** → per-fold/per-regime champion performance rendered as a heatmap; the Diagnose step's written weakness analysis links to the cells it cites → P4, P3 → *Moment:* "Champion weak in fold 5 (2022 bear regime): Sharpe −0.3 vs +1.1 elsewhere" — and the next hypothesis visibly targets that cell.
10. **Fingerprinted composite metric** → user-defined composite (DSL or callable) hashed with SHA-256 at campaign start; every keep/discard decision references the hash; the runner refuses mid-run rewrites → P4, P2 → *Moment:* metric chip showing `sha256:9f3a…` on every experiment; tamper-evident, and labeled exactly that — not Goodhart-proof [survey §6].
11. **Goodhart divergence monitor** → tracks the composite proxy against each raw target metric across the campaign; alerts when they diverge past a band (proxy optimization helps then hurts [D31]) → P4 → *Moment:* an amber banner: "Composite up 4% over last 30 trials; raw test AUC flat — review metric weights or steer."
12. **Multi-seed / CPCV confirmation** → champion candidates trigger a confirmation batch (multi-seed re-runs; CPCV path distribution where protocol supports it [D8][D11][D12]) before promotion; distributional plot stored in the bundle → P6, P2 → *Moment:* "Candidate confirmed: 5/5 seeds improve, spread ±0.004" — or "Rejected: improvement inside seed noise."
13. **Crash-proof checkpointing** → every 5 minutes of reasoning and after every experiment, full state (memory, next command, hardware log, per-fold diagnostics) written to a self-contained markdown checkpoint; a fresh session resumes exactly (PoC §3.4 survived BSODs and a thermal shutdown — founder-reported) → P8 → *Moment:* after a forced reboot, the user types `ascent resume` and the dashboard picks up at "Trial 219 — resuming from checkpoint 03:41."
14. **Winner archive / champion bundle** → on every new global champion: self-contained folder with model, config, code snapshot, filled README, inference script, 14-section audit report (feature importance, calibration, drift, error attribution, limitations, deployment checklist — PoC `winner_archive.py`), reasoning blob, and a reproduction log from an automatic rerun → P9 → *Moment:* a "Champion bundle ready — 14-section audit report" card; Marcus forwards the folder, not a screenshot.
15. **One-command reproduction** → `ascent reproduce <bundle>` on any machine reruns the champion from the bundle's snapshot and diffs the fingerprints → P9 → *Moment:* a stranger's terminal printing "Reproduced: composite 0.6097 vs 0.6097 · fingerprints match" — the single action that turns founder-reported into evidence [survey §7].
16. **BYOK model routing** → user's own LLM keys; router sends Diagnose/Hypothesize reasoning to a frontier model and routine Execute/Document steps to mid-tier, with caching — the $3–60/day economics, typically $3–12 on mid-tier routing [B18][B22] (A12) → P10 → *Moment:* a spend meter: "Today: $4.87 (frontier 12%, mid-tier 88%) — projected $6.10/day," on the user's own bill.
17. **Campaign dashboard + stall detector** → self-contained HTML dashboard (paper App. B.1): sortable experiment table with composite/test/val/commit-hash, metric & equity curves with regime shading, per-fold heatmap, champion panel, CSV/JSON export, live status; stall detector surfaces diminishing-returns patterns with suggested steering prompts (App. B.3) → P4, P8, P9 → *Moment:* phone-friendly page reading "Last 3 experiments diminishing returns — consider: 'research new backbone families'."
18. **Steering console** → high-level natural-language direction ("pivot to new dataset," "self-reflect on stall") is the *only* human input channel; every prompt appended to the durable steering log; the agent must incorporate it into the next hypothesis (constitution §49–52) → P8 → *Moment:* Marcus types one sentence at 7am; by lunch the ledger shows twelve experiments descending from it, each citing the steering entry.
19. **SOTA catalog + subscription** → curated `sota_catalog.yaml` of literature-grounded backbones and recipes per task family (PoC seeded 14 tabular backbones for Higgs), continuously updated as a paid feed; catalog entries carry verified citations so Ground starts warm → P3 → *Moment:* "3 new tabular backbones added this month (TabM-v2, …) — one matches your task; queue it?"
20. **Team parallel campaigns + shared winner archives** → multiple concurrent campaign streams with an org-wide ledger and a shared, searchable archive of every pod's champions and reasoning traces (Team tier; Elena's "campaign memory that doesn't walk out the door") → P2, P9 → *Moment:* Elena searches "volatility regime" and gets every pod's kept and discarded attempts across 6 months, each opening to its full cited reasoning.

## The integration argument

No single feature above is the product, and most are individually copyable — the constitution file itself is open source by design (A11). The power is the closed loop: the **split builder** (4) makes the metric mean something; the **fingerprinted metric** (10) makes keep/discard tamper-evident; the **gates** (5, 8) make each step's output trustworthy; the **ledger** (1) makes the campaign's statistics honest; the **acceptance gate** (2–3) makes "improvement" survive its own trial count; **checkpointing** (13) makes days-long campaigns survivable on a laptop; the **archive and reproduction** (14–15) make the result portable to a skeptic; the **dashboard and steering** (17–18) keep a human technical lead in command at minutes-per-day cost; and the **ledger exhaust** feeds the calibration corpus that makes the next campaign smarter (A11). Remove any link and the chain fails exactly the way the literature documents: ungated loops Goodhart [D30][D31], unledgered champions inflate [D6][D7], ungrounded search plateaus [D28], unverified citations fabricate [D35], and uncheckpointed laptops lose the run. A fork can copy the file; it cannot copy the closed loop's operating history.
